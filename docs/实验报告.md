# 栈点数字商品交易系统实验报告

作者：杜旻橙　学号：2024215314

本文对应当前本地实现，作为技术报告参考稿。工程包含AI辅助生成内容，不作为独立手写声明；实际提交应符合课程规则并如实说明。

## 一 实验目标

综合运用HTML、CSS、JavaScript、React、Node.js和SQLite，实现一个本地可运行的数字商品交易系统。关注完整购买交付链路、清晰的界面和可验证的权限边界，而非真实支付或复杂商业营销。

## 二 实验内容

系统包含访客商品浏览、分类搜索、用户注册登录、演示余额购买、订单和凭证查看、额度调用、兑换码核销、使用记录，以及管理端上新、上下架、补货、近期订单和审计。三类商品分别是API调用额度、兑换码和本地规则服务。

前端采用社区式信息布局：左侧导航、中间商品列表、右侧公告与说明。借鉴NodeLoc首页按分类组织列表的思路，未复制其源码、标志或文章；像素猫使用自绘SVG格子组件。

## 三 实验工具与开发平台

Windows开发环境，Node.js 26.7.0、npm 12.1.0；工程要求Node>=24。React与React DOM 19.3.1、Express 5.3.0、Vite 8.3.7、lucide-react 1.71.0，依赖以package-lock.json锁定。数据库使用Node内置node:sqlite。浏览器检查使用Edge及Playwright，后端测试使用Node内置测试工具。

## 四 系统需求

功能需求：访客能找到商品；买家能登录购买并收到自己的凭证；额度和库存不能为负；管理员可以维护商品；每次使用可查记录。已下架商品不能继续购买，但已购资产仍可查看。

非功能需求：前后端分工清楚；数据库持久化；交易失败能回滚；敏感凭证加密保存；用户间订单隔离；操作结果有提示。当前是本地单实例演示，不包含可用性SLA、真实支付和第三方授权系统。

## 五 系统架构

浏览器React界面通过同源/api接口访问Express。Express负责身份校验和业务规则，通过参数化SQL操作SQLite。Vite生成的dist由Express静态服务提供，因此本地只需要运行一个服务。

数据库由users、sessions、products、inventory、orders、usage、audit组成。users与orders为一对多；products与orders、inventory为一对多；orders与usage为一对多。orders保存商品名称和金额快照，避免历史订单随商品变化。

核心目录为src（前端）、server（后端）、tests（集成测试）、docs（说明）；data存放运行数据，不能混入公开源码包。

## 六 核心模块与关键问题

### 账户与权限

密码采用随机盐+scrypt；会话随机生成，数据库存摘要；Cookie使用HttpOnly和SameSite=Strict。auth中间件统一识别身份，admin中间件限制管理端。本人订单的查询同时使用订单ID与用户ID，防止只改ID查看别人信息。

### 订单一致性

购买涉及扣款、库存分配、订单写入，必须同时成功或同时失败。transaction封装BEGIN IMMEDIATE、COMMIT和ROLLBACK。余额更新有balance>=price条件；兑换码只能选择未使用项。

重复提交还需要幂等：数据库对(user_id,request_key)设唯一约束，收到重复key返回原订单。前端禁用按钮只是减少误操作，不代替后端约束。

### 数字交付

API与服务订单生成随机凭证，兑换码从库存分配。凭证AES-256-GCM加密存储，仅在本人订单响应时解密。API凭证另存摘要用于查找。网页试用和Bearer API调用复用consume，避免两套额度扣减逻辑不一致。

### 安全与异常

使用参数化SQL、请求体大小限制、文本长度校验、安全响应头、写请求Origin校验和简单IP限流。数据库密钥丢失时拒绝启动，避免生成新密钥后无法解密原订单。保存数据和密钥必须一起备份。

## 七 重要代码说明

以下片段来自当前业务逻辑的核心形式，具体上下文见server/index.js和server/db.js。

```js
db.prepare('UPDATE users SET balance=balance-? WHERE id=? AND balance>=?')
  .run(p.price, req.user.id, p.price);
```

扣款与余额条件放在同一SQL语句中，金额单位为分。实际代码还检查changes是否为零；零表示未成功扣款。

```js
db.prepare('UPDATE orders SET remaining=remaining-1 WHERE id=? AND remaining>0')
  .run(order.id);
```

剩余次数条件防止扣成负数，操作与使用记录写入同属事务。

```js
db.exec('BEGIN IMMEDIATE');
try {
  const result = fn();
  db.exec('COMMIT');
  return result;
} catch (error) {
  db.exec('ROLLBACK');
  throw error;
}
```

该事务函数要求同步执行，不应在其中等待外部网络服务。后续接真实支付时应重新设计支付确认与履约流程，而不是把外部请求直接塞入事务。

## 八 测试与实验总结

2026-11-13重新构建成功，Node集成测试10项通过，包含权限、重复订单、买家隔离、额度、单次核销、余额不足、下架、最后库存竞争、Origin与错误凭证、敏感存储、退出失效等断言。测试数量包含一个父测试。

新界面浏览器验证了6件商品显示、分类筛选、搜索空状态、登录和购买确认弹窗；此前版本已验证购买到使用记录的完整链路。没有完成长时间稳定性压测，不能据此宣称生产高可用。

当前实现说明：交易平台的难点不是按钮数量，而是状态的一致性。余额、库存、订单和调用额度都要有服务端约束。界面从大幅宣传卡片改为紧凑列表后，商品对比和信息查找更直接。
