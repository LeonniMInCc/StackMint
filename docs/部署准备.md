# 部署准备与当前边界

目前只完成本地运行，未连接用户云服务器，未改动example.com的DNS或TLS配置。

## 本地启动与备份

Node>=24，执行npm ci、npm run build、npm start。默认127.0.0.1:3000。修改端口时同步修改APP_ORIGIN。正常停止服务后备份整个data目录，保留store.sqlite和vault.key；运行时WAL可能有未写回内容，不要只复制sqlite主文件。

## 部署前必须确认

1. 保留本地演示数据，云端使用独立数据目录。
2. NODE_ENV=production与DEMO_MODE=false同时设置。当前程序阻止生产模式开启演示初始化，但不会删除旧库已有的默认账户，所以不能直接把演示库搬上云。
3. 使用独立数据库注册正式管理员，再用server/admin.js授权；不要公开默认测试口令。
4. HTTPS反向代理转发到本机Node端口，设置APP_ORIGIN为正式https域名。Secure Cookie在HTTP上不可用。
5. 根据实际单层代理配置可信来源，否则按IP限流可能把所有用户当成同一IP。不能盲目信任任意转发头。
6. 配置systemd或其他进程守护、日志轮转、数据库与密钥备份及恢复演练。
7. 防火墙只暴露所需端口，Node与数据库不直接对公网开放。
